# PR rerun 0.8.0

Run `pr-rerun 10 11 12`, optionally with `--repo simpler`, to handle multiple PRs
in one invocation. All PRs use the same selected repository and saved login.

- Each PR has an independent server ownership check, preview, explicit confirmation
  and final state revalidation. Enter or `n` skips only the current PR.
- PRs are processed serially in input order; duplicate numbers are removed. Invalid
  numbers reject the command before reading credentials or making any requests.
- Ineligible PRs and errors are reported without discarding later PRs. A final Rich
  table shows per-PR submission state and request IDs. Accepted requests have not
  necessarily passed CI.
- Ctrl-C or EOF stops the remaining PRs. Earlier accepted requests remain submitted.
  Interrupted or lost confirmation responses are never automatically retried;
  inspect their request IDs before submitting again.
- Exit status is 0 when all unique PRs are accepted, 1 for a decline/interruption,
  and 2 for an error, ineligible PR, partial result or uncertain confirmation. Mixed
  batches return the highest status. Existing repository quotas still apply.

Update clients with `sudo pr-rerun-update --version 0.8.0`. Existing server versions
need no update or restart. Logins, aliases and repository rules are preserved.
Single-PR usage, status, login, policy, statistics, errors and MCP remain compatible.
