# PR rerun 0.9.0

PR authors can request verified reruns with a new `/ci rerun` conversation comment
in repositories that explicitly enable `comment_reruns_enabled`.

- Verify signed GitHub events, immutable author identity, repository installation
  and the original comment; apply the existing workflow, PR and usage policies.
- Persist commands before acknowledging delivery. Deduplicate deliveries and
  comments, expire stale commands and never replay uncertain submissions.
- Keep GitHub writes restricted to reruns. No bot replies, first runs or workflow
  approvals. Existing client logins and CLI workflows remain compatible.
- Add `pr-rerun-admin comment-commands --repo owner/repo` for local audit queries.
- Include a webhook-only Nginx proxy example and bilingual deployment guidance.

Upgrade the API, admin and both collectors before saving the new policy field.
Clients do not need an upgrade. Configure a protected webhook secret, HTTPS relay,
GitHub App Issues read permission and Issue comment subscription, then opt in each
repository. The endpoint is disabled without a secret and repositories default to
disabled. See [comment command setup](../comment-commands.md).
