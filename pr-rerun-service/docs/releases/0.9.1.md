# PR rerun 0.9.1

Unrecognized confirmation input now explains the accepted answers and prompts
again for the same PR, instead of immediately reporting cancellation. Only `y`
confirms; `n` or an empty answer cancels. Case and surrounding whitespace remain
ignored. Invalid input is never echoed or treated as authorization.

The original preview ticket, server-side expiry and per-PR confirmation rules
remain unchanged. Tests cover correction, cancellation, interrupts, and real TTY
input/output for both native portable-client builds.

Update shared clients on each affected machine:

```bash
sudo pr-rerun-update --version 0.9.1
pr-rerun --version
```

Saved logins are preserved. The backend does not need an upgrade. This improves
ambiguous cancellation handling; a reported ordinary `y` cancelling still needs
the affected machine's version and terminal evidence to establish its cause.
See [troubleshooting](../operations.md#confirmation-input-and-unexpected-cancellation-client-091).
