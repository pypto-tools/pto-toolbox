# PR rerun 0.9.3

修复 GitHub PR 接口的 `base.sha` 滞后于实际 PR merge ref 时，错误排除 Full CI 的问题。
PR #3463 的失败运行与合并提交的两个父提交一致，但与该 REST 字段不同。

读取 PR merge ref，校验返回的提交 SHA、恰好两个父提交，以及第二个父提交等于当前 PR head，
再将第一个父提交作为独立验证后的 base，与 Full CI 目标匹配。
不会从运行标题推断 base，也不会在合并信息无法核验时退回使用 REST 字段。
workflow、作者、最新请求选择和提交前复核保持生效，普通 workflow 行为不变。

回归测试覆盖过期或缺失的 REST base 字段、无效或错误的 merge 父提交，以及确认期间和
最终提交前的 base 变化。真实仓库验证只读，不触发 CI。

升级后端并重启 API 即可，无需更新客户端、修改仓库规则或重新登录。
继续兼容 0.9.2 新增的 request 后缀标题。
