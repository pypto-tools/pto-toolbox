# PR rerun 0.7.1

Completed workflows with cancelled jobs are now eligible for a confirmed rerun,
including attempts whose retryable jobs are all cancelled. Previously they were
excluded unless at least one job had failed or timed out.

- Preview and final submission checks include cancelled jobs. If their names or
  cancellation state change after preview, the request is rejected for a new preview.
- Ordinary CI keeps `rerun-failed-jobs`; verified Codex Review keeps `rerun` (all).
  Successful/skipped/active/approval-required runs remain ineligible. The newest
  verified run still supersedes older runs, and PR ownership checks remain enforced.
- The preview JSON adds optional `cancelled_jobs`; `failed_jobs` keeps its meaning.
  The client displays separate Failed and Cancelled lists. It also supports older
  servers that omit the new field.
- Cancellation remains a separate result in CI analytics; failure-rate calculations
  continue to count failures and timeouts only.

**Upgrade the server to 0.7.1 and restart it to enable this behavior.** A client-only
update does not change server eligibility. Update shared clients with
`sudo pr-rerun-update --version 0.7.1` for the new preview display. Existing logins,
repository rules and analytics records remain valid. Previews made before the
server upgrade should be requested again.

This release was validated with simulated GitHub requests, including cancellation-only
and mixed results, fork identities, newest-run selection, and state changes before
each submission. No live PR reruns were performed as part of verification.
