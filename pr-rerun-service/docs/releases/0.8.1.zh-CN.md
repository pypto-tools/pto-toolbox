# PR rerun 0.8.1

通过显式的 `pypto_ci` 仓库身份策略，支持 PyPTO 评论触发的 Full CI。
将 `.github/workflows/ci.yml` 和 `.github/workflows/ci-full.yml` 都配置为
`mode: failed`、`identity: pypto_ci`。

- 从可信 main 分支的 workflow dispatch 历史查找 Full CI，独立于镜像 checks
  和 commit statuses。自动 PR lint 继续受支持。
- 校验仓库、workflow、事件、源分支、PR 作者、head/base，以及 GitHub merge ref
  的 base/head 父提交顺序。PR 响应缺少合并提交时通过独立 ref 查询验证。
- 新旧 workflow 路径共同选取最新 Full CI 请求。较新的成功、进行中或无法验证的
  请求会阻止旧失败运行被重新选中。
- 已结束且含失败、超时或取消任务的运行可以重跑，提交前再次验证目标及最新请求。
  Codex Review 继续使用独立的可信 artifact 校验和 rerun all。
- 历史密集时拆分查询窗口，数据不完整或查询期间变化时停止。服务继续仅支持本人
  PR 的预览、确认和重跑。

保存新规则前需升级 API、管理员命令、统计采集器和错误采集器，因为采集器也会解析
仓库规则。保留数据库和 App 配置。现有客户端、登录状态、别名及多 PR 命令继续兼容。
此次后端适配不要求更新客户端。

详见[仓库规则指南](../multi-repository.zh-CN.md#pypto-评论触发的-full-ci服务端-081)
及[升级指南](../operations.zh-CN.md#升级-pypto-full-ci-支持081)。PR head 或 base
已变化时，需要在 PR 评论 `/ci full` 创建新测试请求。本服务不创建首次运行，也不
批准等待审批的工作流。

通过 612 项测试、Ruff、Pyright、33 项 shell 检查，以及 x86_64 和 ARM64 原生
客户端检查。使用真实 App 对 PR #3395 的 Full CI 做了只读归属校验，未请求重跑。
