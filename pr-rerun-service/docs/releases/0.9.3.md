# PR rerun 0.9.3

Fix false stale-target exclusions when GitHub's PR `base.sha` lags behind the
GitHub-generated PR merge ref. A Full CI run can match the current merge's two
parents while differing from that REST field, as observed on PR #3463.

Resolve the PR merge ref, verify the returned commit SHA and exactly two parents,
and require the second parent to equal the current PR head. Use the first parent
as the independently verified base, then compare the Full CI target against it.
Never derive the base from an unverified run title or fall back to the REST field
when the merge cannot be verified. Existing workflow, author, newest-request and
pre-submission checks remain in force. Ordinary workflows retain their behavior.

Regression tests cover stale/missing REST base fields, malformed and mismatched
merge parents, and base changes during confirmation and final validation. Live
diagnostics are read-only and do not rerun CI.

Upgrade the backend and restart the API. No client upgrade, repository policy
change or new login is required. Request-suffixed titles introduced in 0.9.2
remain supported.
