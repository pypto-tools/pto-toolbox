# PR rerun 0.8.1

Support PyPTO's comment-triggered Full CI through an explicit `pypto_ci` repository
identity strategy. Configure both `.github/workflows/ci.yml` and
`.github/workflows/ci-full.yml` with `mode: failed` and `identity: pypto_ci`.

- Discover Full CI from trusted-main workflow dispatch history, independently of
  mirrored checks and commit statuses. Existing PR lint remains supported.
- Verify the repository, workflow, event, source branch, PR author, head/base and
  GitHub merge ref with ordered base/head parents. Missing merge metadata in the
  PR response is supported through the independent ref lookup.
- Select the newest Full CI request across the legacy and split workflow paths.
  Newer successful, active or unverified requests suppress older failed runs.
- Include completed runs with failed, timed-out or cancelled jobs. Revalidate the
  target and latest request before submission. Codex Review retains its separate
  trusted-artifact verification and all-jobs rerun mode.
- Split dense history windows around GitHub's search cap and stop on incomplete or
  changing results. The service remains limited to confirmed reruns of own PRs.

Upgrade the API, admin launcher, statistics collector and error collector before
saving the new policy. Collectors also parse repository rules. Preserve the database
and App settings. Existing clients, login sessions, aliases and multiple-PR commands
remain compatible. Client updates are optional for this backend change.

See the [repository policy guide](../multi-repository.md#pypto-comment-triggered-full-ci-server-081)
and [upgrade guide](../operations.md#upgrading-for-pypto-full-ci-081).
If the PR head or base has changed, use `/ci full` on the PR to request a fresh test
run. This service does not create first runs or approve pending workflows.

Validation includes 612 tests, Ruff, Pyright, 33 shell checks and native x86_64 and
ARM64 portable-client checks. A live read-only App check verified PR #3395's Full CI
identity without requesting a rerun.
